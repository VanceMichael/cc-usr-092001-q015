# 领域约定

未成年人智能陪伴安全桥围绕**知情同意、风险信号、分级事件、人工介入**保存可核对的业务记录。
所有外部主体使用不含真实身份信息的稳定引用编号（`subject_ref`、`guardian_ref` 等）；
时间一律采用带偏移量的 ISO 8601 字符串，系统保留信号的原始发生时间（`occurred_at`），
绝不用到达时间覆盖它。材料只保存受控引用与 `sha256` 摘要，**不保存可还原的完整谈话**。

## 数据边界（最重要的一条）

入口信号只接受三类内容：

1. 本地处理后的**结构化风险特征**（数值、布尔、受控枚举）；
2. 使用时长等行为统计；
3. 学生主动求助及其类别。

`src/config.js` 的 `SIGNAL_SPEC` 是唯一字段白名单；任何 `text/content/message/transcript`
等疑似原文字段在入口直接以 `422 prohibited_content` 拒收，不入库、不落盘。
信号载荷只存特征、评估器版本、特征模式版本与 `payload_digest` 摘要。

## 知情同意

- 同意决定（`consent_decisions`）**只追加**：现状由同 scope 最新一行决定，历史永不被覆盖。
- 未满 14 周岁：由**经验证的监护人**代为同意/撤回。
- 14–17 周岁：授予需学生与监护人**共同同意**；任一方最新决定为撤回即停止常规监测。
- 成年：学生本人决定。
- 撤回同意后常规监测立即停止；但 `urgent_event`（紧急事件）依法理仍可建立最小事件，
  学生主动求助（`help_request`）始终被接收。已触发的紧急事件继续按既定策略处置，
  不受撤回影响。

## 信号、去重与事件

- 交换事件信封包含 `event_id`、`subject_ref`、`occurred_at`、`source_sequence`、`payload_digest`。
- 来源序号只在同一来源内递增。`(source_id, source_sequence)` 唯一，重传幂等忽略。
- 第二层去重：同主体、同信号类型、同特征语义指纹且处于去重时间窗（见 `DEDUP_WINDOW_HOURS`）
  内的重复信号**只并入同一事件**：计数 +1、追加一次评估快照，不产生新事件、不重复通知。

## 分级与版本

| 等级 | 类别 | 自动动作 |
| --- | --- | --- |
| L1 | 一般依赖 | 自我提醒（仅学生） |
| L2 | 持续孤立 | 联系可信成年人（无则监护人） |
| L3 | 现实伤害线索 | 心理专业人员复核 |
| L4 | 紧急事件 | 即时处置（心理人员、值班教师、监护人） |

规则引擎（`src/rules.js`）是带版本的纯函数注册表：新版本只能追加、禁止覆盖。
事件保存建事件时的 `rule_version`，且**每次**信号评估都在 `event_evaluations`
追加一条版本快照；算法升级后旧判断仍永久按旧版本呈现，自动流程只升不降，
降级只能由人工复核完成。

## 最小披露

每次对外触达在 `disclosures` 登记：收件人、角色、**实际发送的字段清单**、载荷摘要，
并经 `outbox → deliveries` 投递。角色字段白名单在 `ROLE_EVENT_FIELDS`：

- 学生：可读标题、发生了什么、已采取动作、自己的选项；
- 监护人：关怀等级与建议（无任何特征/分数/原文）；
- 教师：在校建议（L4 仅值班教师可见列表）；
- 心理人员：特征、理由、置信度、全部版本快照。

收件箱返回的字段集合必须是登记字段集合的子集；这让复核者能够证明一次升级
**没有暴露多余内容**。

## 可靠投递

通知在数据库事务内写入 `outbox`（pending），投递器在独立事务中完成
“落入 `deliveries` + 翻转 sent”。`deliveries.disclosure_id` 为主键：
服务在任意时刻崩溃或重启，pending 会补发，已落箱的绝不会产生第二封——
重启不丢、仅一次。服务启动时自动补发一次。

## 学生权利

- 决定说明（`GET /v1/events/:id/explanation`）：用了什么数据、没用什么、
  哪个规则版本、可做什么；
- 申诉（`/v1/events/:id/appeal`）：心理人员应答，接受即关闭事件；
- 删除进度（`/v1/me/deletion`）：同步撤回常规监测同意，清除常规事件的特征、
  评估与载荷投影；L4 紧急事件在法定持有期内仅保留等级/状态/时间/法律依据的
  最小壳，持有期与保留事件清单在进度中明示。

## 审计

`audit_log` 为哈希链（每行含上一行摘要），并由触发器禁止 UPDATE/DELETE。
所有访问、同意决定、摄入拒绝（含撤回后拒收、原文拒收）、越权尝试都留痕；
`POST /v1/admin/audit/verify` 可重算全链证明记录未被删除或改写，
从而证明一次复核/升级既未多披露内容，也未因重启丢失。
